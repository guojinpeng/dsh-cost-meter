# 0.4.0 费用统计总览设计建议 / Cost overview design proposal

本文给出 0.4.0「费用统计」页面（侧栏入口 + 主区页面 + 高级设置开关）的调研结论、推荐内容、样式规范和落地拆分。可查看同目录的交互样例 [v0.4.0-cost-overview.html](./v0.4.0-cost-overview.html)。

## 1. 调研结论

参考产品：

- [LiteLLM Spend Tracking](https://docs.litellm.ai/docs/proxy/cost_tracking)：按 key、user、team 统计花费；区分 token 类别（含缓存）；预算与告警；spend logs。
- [Langfuse Token & Cost Tracking](https://langfuse.com/docs/observability/features/token-and-cost-tracking)：按 usage 类型（input、output、cached_tokens）拆分成本；按 model、tag、user 出趋势；花费告警。

市面上的费用页通常回答四个问题：

1. 花了多少（总额、趋势、对比上期）。
2. 花在哪里（模型、会话、时段）。
3. 缓存是否省钱（命中率、节省金额）。
4. 有没有异常（未计价 token、跳过计价的轮次）。

本插件已有数据能覆盖全部四点：projection 保存会话累计、按 route 与按北京时间桶的 token、最近 200 轮结算。因此不需要新的采集通道。

结论：

- 页面按「总览 KPI → 趋势与构成 → 模型与时段 → 会话与口径」四层组织。
- 所有图只用黑白灰阶。缓存读取序列用斜线纹理，不用彩色。
- 费用统计是全局视图，必须汇总所有会话，不能只读当前会话的 projection。

## 2. 推荐展示内容

| 区域 | 内容 | 回答的问题 | 数据来源 |
| --- | --- | --- | --- |
| 概览 KPI | 总花费、总 Token、缓存命中率、已计价轮次 | 花了多少、缓存是否生效 | `buildCostView` 的 `totalMicros` / `totalTokens` / `cacheHitPct` / `turns` |
| 花费趋势 | 按日（或周、月）堆叠：未命中输入、输出、缓存写入、缓存读取；可切换金额 / Token | 支出随时间怎么变 | projection `byTime` 的日期桶，按 `priceRoutes` 重新计价 |
| Token 构成 | 环形图 + 四类 token 数值与占比；缓存节省金额 | 钱主要花在哪类 token | `tokens` 与 `bucketMicros` |
| 模型花费排行 | 模型、花费占比、花费、Token、轮次、缓存命中 | 哪个模型最贵 | projection `byRoute` |
| 时段分布 | 七个北京时间桶的花费条形图；峰时 / 谷时花费与峰谷节省 | 什么时候用得多、谷价是否用上 | `byTime` 的 segment 桶 + `periodMicros` |
| 高花费会话 | 会话标题、最近活动时间、花费 | 哪个会话最贵 | 每会话 `totalMicros` + `sessionQuery.listSessions()` 的 header |
| 口径说明 | 计价来源、未计价 token、币种与汇率、时段与峰谷规则 | 数字可信吗 | config 与 projection 的 `skippedTurns` / `unpricedTokens` |

筛选与交互：

- 时间范围：近 7 天、近 30 天、近 90 天、全部。默认近 30 天。
- 趋势图切换金额 / Token。
- 趋势图悬停显示该桶的四类数值与占比。
- 语言跟随 DSH 语言；主题跟随 DSH 黑 / 白主题，插件不单独切换主题。
- 币种沿用配置项的 `currency`；主金额按该币种显示，另一币种作为辅助值。

不建议放进 0.4.0：

- 预算与告警：需要新的配置项和后台判断，超出本次范围。
- 导出 CSV、分享链接：需求未提出。
- 按 key / tag / team 维度：DSH 没有这些概念。
- 输入框式自定义日期：KISS，先给固定区间。

## 3. 页面结构

```text
侧栏（sidebar.panellist）          主区（main keyed slot）
├─ 新会话                          ├─ 页头：标题 + 时间范围 + 语言 / 主题
├─ 插件                            ├─ KPI ×4
├─ 插件市场                        ├─ 花费趋势（宽） | Token 构成（窄）
├─ 自动化任务                      ├─ 模型排行（宽） | 时段分布（窄）
├─ 上下文洞察                      ├─ 高花费会话（宽） | 口径说明（窄）
└─ 费用统计 ← 新增，order 在插件组末尾
```

侧栏入口与宿主插件管理页使用同一套机制：

- `ctx.slots.register({ name: "sidebar.panellist", id: PANEL_ID, label: () => t("panel"), order }, Icon)`
- `ctx.slots.register({ name: "main", key: PANEL_ID, ... }, CostOverviewPage)`
- 点击侧栏项由宿主调用 `ctx.layout.selectPanel(PANEL_ID)`。
- 客户端插件需在 `package.json` 的 `dsh.client.inject` 增加 `@deepseek-ai/dsh-client-ui-layout` 与 `@deepseek-ai/dsh-client-ui-sidebar`。

开关放在插件高级设置（现有「通用」分组）：

- 配置键：`showSidebarCost`，默认 `true`。
- 关闭后只注销 `sidebar.panellist` 入口，不注销 `main` 页面。这样已打开的面板不会被强制关闭。
- 改动点：`config-store.js` 的 `normalizeConfig`、`schemas.js` 的 `configInputSchema`、`config-draft.js` 的 `buildDraft` / `configOf`、`config-page.js` 的 Switch 行、`locales.js` 文案。

## 4. 样式规范

直接使用 DSH 主题变量，不新增色板：

| 用途 | 变量 / 值 |
| --- | --- |
| 页面背景 | `--dsw-alias-bg-base` |
| 卡片背景 | `--dsw-alias-bg-layer-1` |
| 卡片边框 | `--dsw-alias-border-l1`（浅色 `#0000000a`，深色 `#ffffff0f`） |
| 主文字 / 次文字 / 说明 | `label-primary` / `label-secondary` / `label-caption` |
| 圆角 | 面板 28px，卡片 16px，按钮 8–10px |
| 字号 | 标题 22px / 卡片标题 14px / 正文 13px / 辅助 11px |
| 数字 | 全部 `font-variant-numeric: tabular-nums` |

图表颜色（黑白灰阶）：

- 未命中输入：主文字色（浅色 `#0f1115`，深色 `#f9fafb`）
- 输出：`neutral-bluish-700`（浅色 `#61666b`）/ `300`（深色 `#cfd3d6`）
- 缓存写入：`neutral-bluish-400`（`#adb2b8`）/ `600`（`#81858c`）
- 缓存读取：浅灰底 + 斜线纹理，表示「省下来的部分」
- 只允许链接与焦点环使用 DSH 蓝色，图表不使用强调色

间距：页面左右 32px，卡片内 18–20px，栅格间距 16px。窗口宽度小于 1180px 时 KPI 变两列、其余单列。

## 5. 服务端聚合建议

新增只读接口 `GET ${HTTP_BASE}/overview?days=30`，返回已聚合的视图数据，客户端不再自己扫描会话。

聚合流程：

1. `ctx.sessionQuery.listSessions()` 取会话列表，按 `header.createdAt` 过滤时间范围。
2. 活跃会话：从会话注册表直接读 `stateOf(session, PROJECTION_KEY)`。
3. 已持久化会话：用 `readSession(id)` 重放，并按现有 projection 的 fold 规则取累计值。
4. 按日期、时段、模型聚合 token 桶，用 `priceRoutes(config, route, tokens)` 计价。
5. 结果按会话缓存：持久化日志不可变，可长期缓存；活跃会话每次重算。
6. 返回：`totals`、`buckets`、`byRoute`、`byTime`、`sessions`、`skippedTurns`、`unpriced`、`revision`。

注意：

- `readSession` 会重放完整日志，成本最高。设置时间范围上限和每会话缓存，避免每次打开都全量扫描。
- 「全部」范围只统计可读会话；口径说明要写清范围。
- 金额与 token 的聚合必须共用同一份 price 配置；config 变更后让缓存失效。

## 7. 风险

- 会话多时首次打开慢。用缓存 + 范围上限 + 加载态处理。
- 未计价模型会让「总 Token」与「总花费」口径不一致。页面必须显示未计价说明。
- 全局汇总的金额可能与会话内胶囊显示有小差异（会话内是实时重算）。用同一个 `buildCostView` 逻辑避免。
- 侧栏入口注销后，已打开的 main 页面仍可通过「插件」页返回，不额外做路由清理。
